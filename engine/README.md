# 불변식 엔진 — 체크리스트 없이 취약점 찾기

취약점 **이름을 하나도 모르는** 상태에서, 규칙 6개만으로 검사한다.

## 왜 체크리스트가 아닌가

체크리스트는 오늘 알려진 것만 잡는다. 내일 새 엔드포인트가 생기거나
프레임워크가 바뀌면 리스트 밖에서 사고가 난다.

불변식은 "무엇이 취약한가"가 아니라 **"무엇이 항상 참이어야 하는가"** 를 검사하므로,
검사 대상이 새로 생겨도 규칙을 추가할 필요가 없다.

## 구성

| 파일 | 역할 |
|---|---|
| `discover.js` | 라우트 자동 발견 — 소스 파싱 + OpenAPI + 관용 경로 프로브 |
| `invariants.js` | 불변식 I1~I6. 취약점 이름이 등장하지 않는다 |
| `index.js` | 오케스트레이션 + 3분류 판정 |

## 불변식

| | 이름 | 규칙 |
|---|---|---|
| I1 | 격리 | A의 데이터가 B의 응답에 나타나면 안 된다 |
| I2 | 권한 단조성 | 낮은 권한이 높은 권한의 결과를 얻으면 안 된다 |
| I3 | 익명 차단 | 토큰 없이 사용자 데이터가 나오면 안 된다 |
| I4 | 입력 불신 | 클라이언트 값이 권한·금액을 결정하면 안 된다 |
| I5 | 상태 단방향 | 돈·권한 상태는 역행하면 안 된다 (질문만 제기) |
| I6 | 비밀 비노출 | 서버 전용 값이 클라이언트에 도달하면 안 된다 |

## 판정 (Cloudflare 3분류)

- `confirmed` — 경계 붕괴를 **관측**했고 증거가 있다
- `needs_validation` — 의심되나 미해결 사실이 있다. 심각도를 부여하지 않는다
- `rejected` — 찔러봤고 경계가 버텼다

## 실행

```bash
cd ../experiment/vulnapp && node server.js &
cd ../../engine && node index.js            # 읽기 전용 (안전)
DESTRUCTIVE=1 node index.js                 # 쓰기/삭제 포함
```

기본값은 **읽기 전용**이다. 파괴적 테스트는 실제로 데이터를 지우므로
명시적으로 켜야 한다.

## 검증: 엔진이 모르는 엔드포인트를 잡는가

엔진을 다 만든 뒤, 앱에 **엔진이 존재조차 모르는** 엔드포인트 3개를 추가하고
**엔진 코드는 한 줄도 고치지 않은 채** 다시 돌렸다.

```
라우트 발견: 10개 -> 13개 (신규 3개 자동 발견)
```

| 새 엔드포인트 | 엔진이 잡은 것 |
|---|---|
| `GET /api/v2/workspaces/:id` | I1 교차계정 읽기, I2 권한상승, I6 `api_token` 노출 |
| `GET /api/reports/:id/export` | I1 교차계정 읽기(중첩 경로), I2 권한상승 |
| `GET /api/internal/metrics` | I3 무인증 접근, I6 `db_password` 익명 노출 |

규칙을 한 줄도 추가하지 않았다.

### 덤: 심지도 않은 취약점을 찾았다

엔진이 `GET /api/search` 와 `GET /api/notes` 를 신고했다. 확인해 보니
두 쿼리 모두 `owner_id` 필터가 없어 **다른 사용자의 글이 그대로 반환**된다.
체크리스트 항목 B23(목록·검색 API 권한 필터 누락)에 해당하지만,
의도적으로 심은 21개 목록에도 없었고 `experiment/scanner.js` 도 검사하지 않았다.

```
bob 토큰으로 /api/search?q=Alice
-> [{"id":1,"owner_id":1,"title":"Alice private","body":"alice secret content"}]
```

## 개발 중 잡은 자체 오탐

I2 의 최초 구현은 "관리자와 응답이 같으면 권한상승"이었고,
공개 엔드포인트까지 전부 신고해 **정밀도 1/6 (17%)** 이었다.

응답에 **요청자가 소유하지 않은 레코드**나 운영자 전용 필드가 있을 때만
확정하도록 고쳤다. 증거 없이 같다는 사실만으로는 아무것도 증명되지 않는다.

수정 후 `/api/stats` 는 `rejected`(진짜 공개 엔드포인트)로,
`/api/cards/:id` 는 `rejected`(소유권 검사 정상 동작)로 바르게 분류된다.
