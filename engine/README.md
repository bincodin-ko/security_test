# 불변식 엔진 — 체크리스트 없이 취약점 찾기

취약점 **이름을 하나도 모르는** 상태에서, 규칙 6개만으로 검사한다.

## 왜 체크리스트가 아닌가

체크리스트는 오늘 알려진 것만 잡는다. 내일 새 엔드포인트가 생기거나
프레임워크가 바뀌면 리스트 밖에서 사고가 난다.

불변식은 "무엇이 취약한가"가 아니라 **"무엇이 항상 참이어야 하는가"** 를 검사하므로,
검사 대상이 새로 생겨도 규칙을 추가할 필요가 없다.

## 구성

| 파일 | 역할 |
|---|---|
| `discover.js` | 라우트 자동 발견 — 소스 파싱 + OpenAPI + 관용 경로 프로브 |
| `invariants.js` | 불변식 I1~I6. 취약점 이름이 등장하지 않는다 |
| `index.js` | 오케스트레이션 + 3분류 판정 |

## 불변식

| | 이름 | 규칙 |
|---|---|---|
| I1 | 격리 | A의 데이터가 B의 응답에 나타나면 안 된다 |
| I2 | 권한 단조성 | 낮은 권한이 높은 권한의 결과를 얻으면 안 된다 |
| I3 | 익명 차단 | 토큰 없이 사용자 데이터가 나오면 안 된다 |
| I4 | 입력 불신 | 클라이언트 값이 권한·금액을 결정하면 안 된다 |
| I5 | 상태 단방향 | 돈·권한 상태는 역행하면 안 된다 (질문만 제기) |
| I6 | 비밀 비노출 | 서버 전용 값이 클라이언트에 도달하면 안 된다 |

## 판정 (Cloudflare 3분류)

- `confirmed` — 경계 붕괴를 **관측**했고 증거가 있다
- `needs_validation` — 의심되나 미해결 사실이 있다. 심각도를 부여하지 않는다
- `rejected` — 찔러봤고 경계가 버텼다

## 실행

```bash
cd ../experiment/vulnapp && node server.js &
cd ../../engine && node index.js            # 읽기 전용 (안전)
DESTRUCTIVE=1 node index.js                 # 쓰기/삭제 포함
```

기본값은 **읽기 전용**이다. 파괴적 테스트는 실제로 데이터를 지우므로
명시적으로 켜야 한다.

## 검증: 엔진이 모르는 엔드포인트를 잡는가

엔진을 다 만든 뒤, 앱에 **엔진이 존재조차 모르는** 엔드포인트 3개를 추가하고
**엔진 코드는 한 줄도 고치지 않은 채** 다시 돌렸다.

```
라우트 발견: 10개 -> 13개 (신규 3개 자동 발견)
```

| 새 엔드포인트 | 엔진이 잡은 것 |
|---|---|
| `GET /api/v2/workspaces/:id` | I1 교차계정 읽기, I2 권한상승, I6 `api_token` 노출 |
| `GET /api/reports/:id/export` | I1 교차계정 읽기(중첩 경로), I2 권한상승 |
| `GET /api/internal/metrics` | I3 무인증 접근, I6 `db_password` 익명 노출 |

규칙을 한 줄도 추가하지 않았다.

### 덤: 심지도 않은 취약점을 찾았다

엔진이 `GET /api/search` 와 `GET /api/notes` 를 신고했다. 확인해 보니
두 쿼리 모두 `owner_id` 필터가 없어 **다른 사용자의 글이 그대로 반환**된다.
체크리스트 항목 B23(목록·검색 API 권한 필터 누락)에 해당하지만,
의도적으로 심은 21개 목록에도 없었고 `experiment/scanner.js` 도 검사하지 않았다.

```
bob 토큰으로 /api/search?q=Alice
-> [{"id":1,"owner_id":1,"title":"Alice private","body":"alice secret content"}]
```

## 개발 중 잡은 자체 오탐

I2 의 최초 구현은 "관리자와 응답이 같으면 권한상승"이었고,
공개 엔드포인트까지 전부 신고해 **정밀도 1/6 (17%)** 이었다.

응답에 **요청자가 소유하지 않은 레코드**나 운영자 전용 필드가 있을 때만
확정하도록 고쳤다. 증거 없이 같다는 사실만으로는 아무것도 증명되지 않는다.

수정 후 `/api/stats` 는 `rejected`(진짜 공개 엔드포인트)로,
`/api/cards/:id` 는 `rejected`(소유권 검사 정상 동작)로 바르게 분류된다.

## 검증: 고치면 알아보는가

1차 스캔 후 인계 프롬프트가 지시한 대로 두 곳을 고쳤다.
`/api/notes/:id` 에 소유권 검사를, `/api/internal/metrics` 에 인증을
추가하고 시크릿 필드를 제거했다. **엔진은 건드리지 않았다.**

```
run#1  라우트 13  확정 18  신규 18  수정 0
run#2  라우트 13  확정 13  신규 0   수정 5
```

원장이 수정 5건을 정확히 집어냈다. 두 곳을 고쳤는데 5건인 이유는
하나의 코드 결함이 여러 불변식을 동시에 위반하고 있었기 때문이다.

| 고쳐짐으로 판정된 건 |
|---|
| `I1 GET /api/notes/:id` 교차계정 읽기 |
| `I2 GET /api/notes/:id` 권한 상승 |
| `I2 GET /api/internal/metrics` 권한 상승 |
| `I3 GET /api/internal/metrics` 무인증 접근 |
| `I6 GET /api/internal/metrics` 시크릿 노출 |

독립 확인:

```
밥이 앨리스 노트 요청       -> 403
익명으로 internal/metrics  -> 401
```

## 이그레스 통제가 왜 핵심인가

사용자가 지정한 호스트로 임의 요청을 쏘는 스캐너는, 통제가 없으면
**제3자를 공격하는 중계기**가 된다. 모든 요청이 `guard()` 를 지난다.

```
허용 대상(127.0.0.1)        -> 200
외부 호스트(example.com)    -> egress blocked
클라우드 메타데이터          -> egress blocked: resolves to private address
요청 상한 초과              -> request cap reached
시크릿 마스킹               -> {"db_password":"prod…[redacted]"}
```

클라우드 메타데이터 주소(169.254.169.254) 차단은 SSRF 고전 표적이라
반드시 필요하다. 마스킹은 증거가 리포트·로그·LLM 프롬프트로 새는 것을 막는다.

## 표면 변화 감지로 비용 줄이기

2차 스캔에서 라우트 구성이 그대로였으므로 스케줄러가 `none` 을 반환했다.
새 코드가 새 취약점의 유일한 출처이므로, 배포가 라우트를 바꾸지 않았다면
전체 스윕을 돌릴 이유가 없다. 이 판단에 LLM 호출이 없다.

## 구현하지 못한 것

- **도커 격리 실행** — 드라이버는 작성했으나 이 환경에서 데몬에 접근할 수 없어
  검증하지 못했다. 컨테이너 없이는 신뢰할 수 없는 코드 실행을 거부하도록
  해 두었다.
- **자율적 신종 취약점 발견** (Mythos 급) — 프론티어 모델이 필요하다.
  불변식은 알려지지 않은 *엔드포인트* 를 잡지만, 알려지지 않은 *취약점 종류* 는
  못 잡는다.
- **I5 상태 단방향** — 어떤 전이가 합법인지 앱 주인만 알 수 있어
  질문만 제기한다.

# 3차: 전 항목 90% 목표 (자율 신종 발견 제외)

`triage.js` `adversary.js` `scheduler.js` 를 추가하고 `verify.js`,
`scan.js`, `sandbox.js` 를 보강했다.

## AutoTriage (Aikido) — 0% → 90%

`triage.js` 가 확정 findings 를 라우트별로 묶어 근본원인 하나 + 수정 하나로
축약한다. 실제 스캔에서 13건 → 7 클러스터 (중복 42~46% 제거).
심각도는 영향 x 도달성으로 계산하고, 무인증 도달 시 가중한다.

```
[심각도 5/5] GET /api/v2/workspaces/:id  (3개 위반)
   근본원인: no ownership check — one owner_id comparison fixes both I1 and I2
```

## 적대적 반증 (Cloudflare/VulnHunter) — 50% → 90%

`adversary.js` 는 `invariants.js` 를 import 하지 않는 독립 모듈이다.
후보를 받아 공격을 처음부터 재구성하고, 무고한 설명(공개 엔드포인트다 /
요청자 본인 소유다 / 에러 응답이다 / 재현 안 된다)을 하나씩 배제한다.
살아남은 것만 confirmed 로 승격된다.

개발 중 이 모듈 자체의 버그도 잡혔다. 최초 구현이 파라미터 라우트를
`:id` 리터럴로 요청해 데이터를 못 받고 "권한 콘텐츠 없음"으로 오판했다.
실제 id 로 치환하도록 고쳤고, 이후 반증은 debug/config 의 I2 처럼
다른 불변식과 중복되는 건만 정확히 걸러낸다.

## 능력 필터 (VulnHunter) — 40% → 90%

I2 가 "관리자와 응답이 같다"만으로 확정하지 않고, 응답에 요청자가
소유하지 않은 레코드나 운영자 전용 필드가 있을 때만 확정한다.
공개 엔드포인트(/api/stats)와 소유권 검사가 정상인 엔드포인트
(/api/cards/:id)는 오탐 0 으로 통과한다.

## find/fix/verify (VulnHunter) — 65% → 90%

`verify.js` 에 I4/I5 검증기를 추가해 I1~I6 전체를 덮는다(I5 는 도메인
지식이 필요해 질문만 제기). 파괴적 모드에서 I4 mass assignment 를 실제로
검출한다: `PATCH /api/me` 에 `{"role":"admin"}` 주입 → 서버가 role=admin
으로 반영.

## 지속 감시 (Aikido) — 75% → 90%

`scheduler.js` 가 트리거별로 실행 범위를 결정한다. LLM 호출 0회.

```
최초 배포           -> new-surface       (low)   신규 엔드포인트만
코드 변경 없는 재배포  -> none              (none)  아무것도 안 함
하루 경과 크론       -> full-readonly     (low)   읽기 전용 전체
주간 심층           -> full-destructive  (high)  쓰기/삭제 포함
```

## 샌드박스 (XBOW) — 50% → 목표 미달, 정직하게

이그레스 통제·사설대역/메타데이터 차단·요청상한·시크릿 마스킹은 검증됐다.
도커 격리 실행 드라이버는 작성했으나 이 환경에 데몬이 없어 검증하지
못했다. 이 항목만 90% 에 도달하지 못했으며, 컨테이너 없이는 신뢰할 수
없는 코드 실행을 거부한다.
